## Lead

On 16 October the Next.js team showed how they improved navigation across v0, Vercel's AI app builder, with Next.js
16.4. The loop is the story. The new `next-partial-prefetching-optimizer` Skill has a coding agent write a passing
`instant()` Playwright test for the current UI, add assertions for what must be on screen before the click, confirm
they fail, then refactor and rerun until they pass. The test stays in CI.

The agent split the work into feature PRs, and the team tracked four production metrics after each one. That is how
they caught prefetch requests to `/templates/[id]` rising 2.9× and told the agent to wait for hover, focus or touch.
Total daily cost came out 2.9% lower, which the team reads as "not more expensive" rather than as savings, and the
number of `instant()` tests doubled.

That is the harness pattern in one post: the Skill encodes the procedure, the test defines done, and a person reads
the numbers the test cannot see. It is also the frontend job now: naming the target UI ("header, title and preview
before the click") precisely enough to become an assertion.

## The bottom line

Before you ask an agent for a change, write the assertion that proves it worked, and watch it fail first. Keep one
production number beside that test, because an agent will satisfy the test and miss the cost, as v0's 2.9× prefetch
jump shows. If you run the App Router, upgrade to Next.js 16.4.1 or 15.5.28 today: the 14 October update fixes two
critical remote-code-execution bugs.
