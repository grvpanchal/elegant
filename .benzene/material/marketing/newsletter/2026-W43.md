## Lead

On 19 October Vercel open-sourced durable-harness, which brings crash safety to Pi, OpenCode, Codex and Claude Code. Before a model or tool call runs, the harness records an intent; when the call finishes, it records the outcome, and the turn is backstopped by a queue message. If the function dies, a new one reads the log and picks up where the last one stopped.

After a crash the log says what finished, what was running and what never started. Completed calls never run again, so you are never billed twice for a finished model call's tokens. Interrupted tools marked `replay: 'safe'` run again; any other tool comes back to the model as possibly run — a tool that posts a PR comment is marked `'never'`, so it cannot post twice.

Deciding which actions are safe to repeat is now frontend work: it is the State question of what a turn has actually done, answered in one durable log instead of two memories.

## The bottom line

Walk the tool list your agent exposes and write down, per tool, `safe`, `never` or `check` — that annotation is now the crash-recovery policy, not an ops afterthought. Then name the model in your config rather than accepting whatever the harness defaults to: six Copilot models left service on 19 October, and Copilot's model policy API is how enterprise, orgs and teams pin what replaces them. Finally, treat the transcript as a cache of a durable log, not the truth, and decide which of your own tools are safe to replay and which must never run twice.

## Practice question

**Retry a request with backoff** — <https://elegantfrontend.training/practice/retry-with-backoff.html?utm_source=newsletter&utm_medium=email&utm_campaign=agent-durability>

If a crash makes an interrupted tool "possibly run", your request layer must decide what is worth retrying, back off exponentially with jitter, and stop when the caller walks away. Do it before you annotate a single tool `safe`.
