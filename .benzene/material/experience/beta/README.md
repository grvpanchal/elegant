# Beta reports

One report per CTO change in beta or review in `.benzene/changes.json`, written by the beta-test cell before the CEO's final approval and named `<change id>.md` in this folder. Each report is YAML front matter in the beta-test skill's format: `change` (the id), `title` (the change's title), `persona` (one of P1 to P4 from `../ux-model.md`, for example a laid-off React developer about 5 years in), `tasks` (the 3 to 5 things that persona tries on the changed pages), `passed` (what worked), `failed` (what did not, specific), and `severity` (none, minor, major or blocker, where a blocker stops the persona's task). The cell reads the change's files in the worktree path changes.json names, and the page it changes, before judging; it is a simulated walk-through by a persona, not feedback from a real person, and never names one.
